## How to read this

**Method.** 49 Hub search queries (the list is in the script) produced the candidate pool; each
candidate was then read with `HfApi.dataset_info(id, files_metadata=True)` for its card, licence
field, tags, per-config `download_size` / `dataset_size` / split example counts, and repo file
sizes. **No dataset rows were downloaded, no model was called, and nothing in this catalog was
used for training** — §7 of the loop ADVISORY puts that out of scope. Everything below is
metadata plus curation; the only text read from a dataset repo is its card (`README.md`) and,
for one id, the repository's licence file.

**Columns.**

| column | where it comes from |
|---|---|
| dataset id | the Hub id, copied verbatim |
| size (Hub) | card `dataset_info` sums: download size, row bytes, example count. When the card carries no `dataset_info`, the sum of the repo's file sizes is used and the cell says `repo files`; if the card reports neither, the Hub size-category tag is shown instead |
| labels | curated provenance, one of `human`, `structured`, `heuristic`, `llm`, `unknown` (see below) |
| licence | the card's licence field; if absent, the Hub licence tag; if both are absent, `UNKNOWN` — never guessed. A curated override is used only when the card field is empty or `other` and the licence is declared elsewhere in the repo (the note says where) |
| convertible | which typed-decision qtypes can carry an item built from this dataset, and the field the gold comes from |
| overlap risk | the MedDecide-Bench tier-1 source the dataset touches, if any, and the kind of overlap |
| verdict | `train-candidate` / `eval-candidate` / `reject` |
| reason | one line saying why the verdict follows |

**Label provenance.**

- `human` — labels or keys written or judged by people (annotators, clinicians, exam authors,
  fact-checkers).
- `structured` — labels are a field of the source record (a registry code, a label section, a
  computed value), not a judgement about text.
- `heuristic` — labels derived by a rule from text (e.g. `pqa_artificial`).
- `llm` — labels generated by a language model.
- `unknown` — the card does not say.

**Convertibility test.** A dataset is convertible only if an item can be built whose gold is a
structured or human field, with the answer-bearing text removable from the state. The
`convertible` column names the qtype(s) and the `reason`/overlap text names the field; a dataset
whose labels are span offsets, free text, or images with no discrete gold is marked `no`.

**Verdict rules used here.**

- `train-candidate` — official **train** split or pre-window structured-gold items, human or
  structured labels, a licence that permits openly-released weights (or an S5-approved tier-1
  source), and no tier-1 test-split overlap. Share-alike licences are allowed with the obligation
  written into the reason.
- `eval-candidate` — usable for evaluation but not for training: test-only or validation-only
  release, non-commercial licence, undeclared licence, unresolved record-level overlap, or a
  gold field that needs checking first.
- `reject` — tier-1 test split, LLM/heuristic gold, credentialed or restricted data, duplicate
  packaging of a listed id, or no convertible gold field.

**Licence policy** (applied consistently, stated here so a reviewer can disagree with it once):
non-commercial licences (`cc-by-nc-*`) → `eval-candidate` at most, because model weights are
released openly; share-alike licences → `train-candidate` with the obligation named; undeclared
licence → `eval-candidate` at most; a named non-SPDX licence (`other (NAME)`) is judged by its
name.

**Limits.** Sizes are Hub-reported, not measured downloads. Overlap risk is a *source-level*
assessment; the record-level leakage check is S6's job, and a `train-candidate` here still has to
pass it. Card claims were not verified against rows.

**Ranked first five to train on** (of the 14 `train-candidate` rows):

1. `bigbio/evidence_inference` — human PICO prompts with the direction of the result; the only
   candidate that yields `choice`, `score` and `noul` items from one human gold field, MIT
   licensed, and its only overlap is PubMed abstracts (pre-window PMIDs).
2. `ncbi/MedCalc-Bench-v1.2` — deterministic calculator gold with an official train split; the
   cleanest `score` source in the list.
3. `openlifescienceai/medmcqa` — the largest human-keyed item pool whose train split is already
   allowed by S5; only the official train split may be used.
4. `BeIR/scifact` — expert-written claims with support labels; the S5-approved train split feeds
   the record–claim consistency templates directly.
5. `chrisvoncsefalvay/vaers-outcomes` — structured regulatory gold with official train/val/test
   splits, so the split boundary is the publisher's, not ours.

(`BeIR/nfcorpus` and `bigbio/pubhealth` are the next two; both are `train-candidate` with a
restriction noted in the row.)
