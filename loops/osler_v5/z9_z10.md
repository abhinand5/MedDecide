## Readings made before the runs (ADVISORY §10 left these open)

1. **"Calibrated as in the Z1 probes."** Z1 fitted no temperatures (its docstring and probes.md §5 say so: accuracy only). ADVISORY §10
   therefore cannot mean Z1's method literally. Z9 uses the method osler_v4 used for the final (Y8's `model.json` calibration): one
   temperature per question type, fitted by NLL on fast dev v4 (17,532 items), separately for each setting, then applied to every dev set
   of that setting. A temperature does not change any argmax, so the accuracy figures are unaffected (the script asserts this per item);
   the Brier scores are the calibration-dependent part. The refit for the final's own readout is checked against Y8's saved values.
2. **Clef-Flash data rule (ADVISORY §10 Z10.2).** The weights run locally only if three checks pass: the snapshot is the pinned
   revision (fde727a2), the authors' code holds no network client or URL outside a reviewed allowlist (empty by default), and the model
   loads and scores two public panel items with the network disabled (`HF_HUB_OFFLINE`, `TRANSFORMERS_OFFLINE`). The record is
   `outputs/osler_v5/Z10/clef_local_check.json`. `scripts/osler_v5/z10_clef.py` refuses to run without a passing record for the same
   snapshot, and it applies that gate to every Z10 set, because the MR templates' sources are not all public and MedNLI is built
   from MIMIC-III notes. If the check fails, every Clef cell is NOT MEASURED.
3. **MedNLI is treated as MIMIC-derived** for the data rule (its premises come from MIMIC-III clinical notes; AGENTS.md).
4. **Qwen zero-shot readout.** Qwen3.5-4B and -9B are scored with osler_v4's Y4 zero-shot readout (the W5 runner's prompt and letter
   probabilities, one item at a time, single order). The osler_v4 zero-shot pplx baseline on these sets was scored with the authors'
   code, so the two readouts are not the same code path. The knowledge pairing against pplx is therefore a comparison across readouts,
   and it is labelled that way.
5. **Readout-health gate.** Zero-shot Qwen cells get the full D12 check of `meddecide.eval.health` (median label mass ≥ 0.5, greedy
   agreement, accuracy CI not below chance, constant answer), with the greedy check read from the full-vocabulary argmax flag as
   osler_v0's O2 scoreboard did. Clef-Flash's readout normalises over the offered options, so it gets the D21 checks only (constant answer
   and CI not below chance). A failing cell is named and left out of every reported accuracy; its count is printed beside the numbers.
6. **Knowledge test denominator.** The knowledge set has 5,456 items; 5,435 are paired with osler_v4's zero-shot pplx (21 are not scored by
   the authors' code, osler_v4 gate_o4.md). Accuracy is reported on the paired items, and the all-items figure is labelled.

**Readings (ADVISORY §10 Z9.3 and Z9.4, fixed before the run).**
1. **The base readout alone does not fix positional health.** With pplx's step-0 readout, the two-letter accuracy is 0.1924 against a
   limit of 0.3723 (half the single-letter 0.7445), and it fails in all three orders (C080). The first evidence the readout hypothesis
   needed would have been a pass. There was none, so the readout is not the sole cause of the two-letter collapse. The Z1 readout
   split had already shown the same (C035).
2. **The adapter is the next suspect (Z9.4).** Positional health still fails with the base readout, so, as the pre-registration says,
   a frozen-readout training arm (Z11, not queued) is not expected to fix two-letter accuracy alone. Both configurations are reported.
3. **The base readout's probabilities are flatter than its accuracy supports.** Its fitted temperatures are below 1 (C081): NLL on
   the choice items falls from 0.758 to 0.498 when they are applied, and CG v2 Brier falls from 0.437 to 0.334. The trained readout's
   calibration is smaller (CG v2 Brier 0.356 to 0.348; C086).
4. **Knowledge falls with the adapter, before the trained readout is added.** Both settings are below zero-shot pplx on the dev
   knowledge items, and both intervals exclude zero: -0.0165 for the base readout and -0.0140 for the trained one (C079, C084). The
   base readout's point estimate is the larger drop, and the intervals overlap, so the two are not distinguished here. The knowledge
   drop therefore does not need the trained readout. This is an additional reading; no choice uses it.
5. **Single-letter accuracy falls with the trained readout.** In the original order it falls from 0.7445 (base readout) to 0.6407
   (trained; C039 has the same value), and under the seeded permutations it is 0.5540 and 0.5604 against 0.7053 and 0.6698 for the
   base readout (C080, C085).
